ChronoLog Observability — Data Flow

How an agent fleet on the cluster becomes live views. Two capture paths feed two stores: ChronoLog is the durable, ordered cold path (teal); an in-process hot store + SSE bus is the instant live path (amber). Every dashboard tab is tagged with the store it reads — that split is why the live views are real-time while full-fidelity history fills in after the ~180 s keeper→grapher drain.

Read it as a demo map. Top: the agent fleet across cluster nodes (Beat 1). Middle: two capture paths — Path-A (LLM turns → spool → capture worker) and Path-B (inter-agent calls → collector → keeper). These fan into two stores: ChronoLog (durable, ordered — fills the Workspace/Interactions tabs after the drain) and the hot store + SSE bus (instant — powers the ★ live Scenarios/Cluster views, Doctor, Traces, Memory). The amber arrows are what the audience watches update in real time; the teal arrows are what makes it durable and complete. The ribbon is the positioning: this is the only tool that draws the agent graph and the machine graph together.
