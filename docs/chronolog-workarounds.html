Concepto base

¿Qué es el GIL? → el «bastón de hablar» de Python

Imagina una reunión donde solo puede hablar quien tiene el bastón. En Python pasa eso: aunque haya varios hilos trabajando, solo uno ejecuta código a la vez — el que tiene el bastón (el GIL, Global Interpreter Lock). Se lo van pasando tan rápido que parece que trabajan a la vez.

La regla de oro: un hilo educado, cuando se va a quedar esperando algo lento (disco, red), suelta el bastón para que los demás trabajen mientras él espera.

El bug

ChronoLog agarra el bastón y no lo suelta

El cliente de Python de ChronoLog (py_chronolog_client) está mal educado. Cuando llamas a ReplayStory («dame los eventos de esta story») y esa story todavía no está lista, la llamada se queda esperando… pero NO suelta el bastón.

Resultado: se queda con el bastón agarrado esperando para siempre (no hay timeout). Y como nadie más puede cogerlo, se congela TODO el dashboard — no solo un hilo, todos. Pulsa el botón rojo del demo de arriba para verlo.

Por qué pasa

La ventana de drenado (~180 s)

¿Por qué una story «no está lista»? Porque ChronoLog guarda los datos en fases. Durante el tránsito hay una zona en la que la story está «sin drenar» = en tierra de nadie. Si la pides justo ahí → cuelgue.

KEEPERlo recibe (memoria)
DRENANDO… ~180 s⚠ zona peligrosa
GRAPHERCSV en disco (listo ✓)
Si pides la story dentro de la zona rayada → 💀 cuelgue del GIL

Las vistas en vivo siempre caen aquí, porque enseñan lo que acaba de pasar — justo dentro de la zona peligrosa.

La solución

No preguntes en la zona peligrosa: lee de tu propia copia

En lugar de pedirle a ChronoLog en vivo (riesgo de cuelgue), guardo una copia local de cada evento. El dashboard lee de mi copia: instantáneo y sin bastón. ChronoLog queda solo para el histórico viejo, que ya está drenado y es seguro.

📓 Mi copia local
JSONL / CSV en disco · lectura instantánea · GIL-safe ✓
→ lee aquí
❄️ ChronoLog
solo histórico viejo (ruta fría, ya drenada)

Regla: nunca pidas en vivo algo que pueda estar sin drenar. Lee tu copia; ChronoLog solo para lo antiguo.

El otro problema (sin GIL)

ChronoLog es una biblioteca sin catálogo

Esto no tiene nada que ver con el GIL. ChronoLog no tiene una función en Python para listar lo que guarda (le falta el binding ShowChronicles). Puedes sacar un libro si sabes el título exacto, pero no puedes pedir «la lista de todos los libros».

Mi apaño: me monto mi propio catálogo a mano. Cada vez que aparece un escenario / sesión / host nuevo, lo apunto en un chronicle especial llamado __index__. Cuando quiero la lista, leo mi catálogo en vez de preguntarle a ChronoLog (que no sabe responder).
